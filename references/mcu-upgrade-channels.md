# 板级固件升级通道：选型与预留（画板前定）

目标：板上留两条路 —— ①**常规升级**（不用开盖）；②**救砖**（应用跑飞/变砖）。

## 一、先问四个问题（任何 MCU 家族都适用）

1. 这颗 MCU 有 **ROM bootloader（system memory）** 吗？支持哪些外设、用哪几个脚？——查原厂"system memory boot mode"应用笔记的逐系列表（ST 是 AN2606：支持的外设 + Bootloader ID + 内存地址 + 每个外设用的**具体脚位**）。
2. 板上那个外设在 **bootloader 模式下真的能用**吗？（见二）
3. **BOOT0（或等价入口）物理上可达吗**？硬下拉或只有一个测试点 = 没有救砖入口。
4. 能不能**不用 ROM bootloader**，用应用内 IAP 自己升级？（通常更好，见四）

## 二、外设"复位后默认状态"是决定性的

- ROM bootloader 只在**它支持的那几个外设的固定复用脚**上监听；脚位与原理图网络对不上就不算可用。
- **由 MCU GPIO 控使能的收发器，复位后使能脚是悬空的**：很多隔离/工业 485、232 收发器 **DE 内部弱下拉、RE 内部弱上拉 → 接收器被关掉** → 这类串口**做不了 ROM bootloader 通道**（只能应用内 IAP）。查法：翻收发器手册 "Logic Input / Input equivalent circuit" 一节的内部上下拉描述。
- **只有 TXD/RXD、没有使能脚的 CAN 收发器**复位即可用 → **CAN 通常是最干净的 ISP 口**。
- 经典 ROM bootloader 外设：USART×n、I²C×n、SPI×n、**FDCAN**、**USB-DFU**（USB FS 常"不需要外部上拉"）；**一般不含以太网** → 网络升级必须自己写 IAP。

## 三、硬件上值得预留的（成本几元，价值极高）

- **BOOT0：10k 下拉 ＋ 跳线/按键到 VDD**（必留）。
- 可选 **USB 座 → USB_DP/DM**：USB-DFU，最通用、最快。
- 可选 **UART 排针（TX/RX/GND/3V3）**：调试日志 ＋ USART ISP。
- **SWD 座保留兜底**：没有 NRST 也能烧；复位用软件 `NVIC_SystemReset()` 或看门狗，不必为升级加线。

## 四、应用内 IAP 设计要点

- **双 bank ＋ read-while-write** 的型号才能"边跑边写另一个 bank" → 校验后置 bank 交换标志 → 复位生效；**产品必须有失败自动回滚**。
- 触发分层：应用内命令（收到升级指令 → 写标志 → 软复位进 bootloader）＋ BOOT0 硬件兜底。这样日常升级连 BOOT0 都不用碰。
- 提前定：bootloader 区 + A/B 应用区（各半 bank）分区、传输通道（网口 TFTP/HTTP 或 CAN/串口自定义帧）、完整性校验（CRC ± 签名）、版本与回滚标志。
- 升级通道要写进"软硬对接文档"：接口、速率、进入/退出条件、失败行为、升级时对外设的影响（例如升级期间某路输出是否要关）。

## 五、USB 通道与"断电能不能升级"（2026-10 实补）

**Type-C 座做 device 的必做项**：
- **CC1 与 CC2 各一颗 5.1kΩ 到 GND（Rd）必须放** —— Type-C 主机靠 CC 上的 Rd 判断"有设备接入"，缺了它 **主机根本不给 VBUS**（用户常漏这颗）。
- VBUS 要不要接进 MCU：① 当作**"插入检测/升级触发"**信号 → 两颗电阻分压到 ≤3.3V（如 22k/33k → 3.0V；别用两颗 10k 得 2.5V，可能低于 OTG 的 VBUS 感知阈值）；② 若同时要用 OTG 外设本身感知会话 → 优先用芯片指定的 **OTG_FS_VBUS** 脚（多数 STM32 上就是某个 USART 的 TX 脚，会与 UART ISP 通道抢脚位，二者只能选一）；③ 干脆不接 → 固件里关掉 VBUS sensing，USB 数据照样通，只是少了"插入即升级"的触发条件。
- **VBUS 通常不并入板内电源**（避免争电/倒灌）——除非明确要做 USB 供电方案。

**"其他都断电时能不能升级"必须先分清两种断电**（回答用户前先问/先判）：
- **输出全关但整机通电** → 只要能保证**控制域供电独立于输出通道**，就**能**升级/救砖；这是推荐的产品形态。
- **整机断电（拔 220V）→ 要 USB 单独供电**：需要 ① **电源 ORing**（理想二极管/电源多路复用，普通二极管 0.5V 压降会卡低压 buck 的输入下限）；② **5V 负载分区**（整板 5V 域常 1.5~2A，远超声 Type-C 口的 500mA/900mA 能力，插上就限流拉崩）＋ 软件按 VBUS 有无关外设。**一般结论：不划算，别做**；据实告诉用户"升级/救砖需整机通电（输出可全关）"即可。

**ROM bootloader 的"会不会回不来"要讲清**（用户必问）：
- 它在**出厂只读的系统存储区**，**不在用户 Flash 里 → 擦不到、刷不坏**；能刷坏的只有用户 Flash、选项字节、保护等级。
- 唯一"回不来"= 开了**不可逆读保护**（ST 的 **RDP Level 2**，会永久锁死调试/引导通道）→ 防抄板用可逆的 **Level 1**（解锁＝全片擦除，仍可救）。
- 顺带提醒：RDP 关闭时，拿到板子的人用 BOOT0 就能读走固件——产品要防抄要开 L1。

**自写 IAP 的硬理由（按强度排序，别过度设计）**：
1. **新固件刷坏要能自动回滚** —— ROM bootloader 只管"把数据写进 Flash"，**不管新固件能不能跑**；现场刷坏仍要开盖重刷 → 这才是产品必须自写 IAP 的最硬理由。
2. **不开盖/远程触发**（屏上菜单、上位机命令、插网线自动进入）。
3. 定制协议（加密/签名、断点续传、批量广播、升级日志、进度显示）与以太网通道（ROM 不支持以太网）。
→ 以上都不需要时，**零代码用 ROM bootloader 就够**；硬件先把 USB 座/CC/ESD/BOOT0 跳线一次做全，软件可后补 IAP（不必动板）。
