# 交付前收尾全检——真假报分诊与口径

配合 SKILL.md 阶段 3.8。**工具命令与字段定义在 `easyeda-agent` 技能**（`references/pcb.md`、`references/pcb-routing.md`）。
本文只写**判据与口径**：哪些条目是真缺陷、哪些是工具/口径造成的假报、以及结论该怎么讲。

## 1. 四类数据源的口径

| 来源 | 说明什么 | 能不能单独下结论 |
|---|---|---|
| `pcb drc`（原生） | 按**板上真实规则**算的间距/短路/连接 | **能** —— 电气结论以它为准（`passed` + `violations`） |
| `pcb report` | 每条网的实际铜长、差分对 P/N 长度与 `skew`、等长组 `spread` | 能 —— 定量证据（差分对要先建约束才有数） |
| `pcb check`（DFM 启发式） | 原生 DRC 不覆盖的工艺/DFM 项 | **不能** —— 逐条分诊后再报 |
| `pcb dump --include-copper` | 全板对象快照（器件/焊盘/轨/过孔/铺铜与实际铺铜/禁布区/填充与挖槽/板框） | 是原始事实，含义要自己解读 |

## 2. 必须先分诊的假报

- **规则值单位没归一** → 海量 `clearance` / `copper-near-edge` / `width-under-spec`：一旦报出的规则值是**三位数 mil**（真实规则量级是几 mil~几十 mil），这批结论就是单位错位，不能当违规报给用户；改用原生 `pcb drc` + 工具自报的**实测距离**（「runs 105.5mil from pad …」）判断。
- **`power-not-poured` 会被 fill 骗**：规则只认 `pour`/PLANE，不认**静态填充铜**——用 `pcb fill` 大面积配电的电源网照报「无铺铜」。先确认该网确有 fill/平面覆盖。
- **`via-in-pad` 的散热孔阵列**：功率 IC 中央散热焊盘上成排的同网过孔是**预期设计**（散热），落在普通信号焊盘中心的才要改。
- **`silk-over-pad` 成百上千条**：丝印压焊盘，贴片厂自动裁，功能无影响。
- **非矩形板框**：dump 的 `outline` 退化为 AABB 近似（带 `format: unexpected-start:` 提示）→ 板边距离是近似值，不能据此断言「铜离板边太近」。
- **自动命名网络上的铺铜**（`$xNyy`）：先从原理图回读该网成员——隔离侧电源节点（VISO/隔离总线）本来就是自动命名网，铺铜正常。

## 3. 必须落进报告的真缺陷

- **悬空铜 / 悬浮铜岛**：`dangling-end`（轨端不接任何焊盘/过孔/轨）与 `floating-track-island`（≥2 段互相锚定、整组不接任何焊盘——前者看不见这种）。给坐标，让用户删掉或接上。
- **单层过孔**：只碰到一层铜、不换层的过孔＝无用孔，删掉或让它真接到另一层。
- **去耦电容离 IC 太远**：报具体距离（目标 ≤2mm），功率/PHY/交换机附近的 100nF 优先挪。
- **缺基准点（Fiducial）**：有 SMT 规模焊盘却没有基准点 → 建议加 3 个 1mm 非共线基准。
- **丝印文案笔误**：把全部丝印文字**去重打出来**人工过一遍——实测抓到输出标注被重复写成同一个名字；用户对标注/文案较真，这类必报。
- **锐角/酸性角、轨穿过同网焊盘未终止**：小项，列出来让用户决定改不改。

## 4. 功率路径载流自检口径

大面积 fill/plane 是**干线**，但**被串联进电流路径的细线段才是瓶颈**——只看「有铺铜」会漏判。报告时：
- 点名让用户逐处自查：① 输入座 → 保护/热插拔级；② 保护级 → 各路降压输入；③ 每路输出 → 端子；④ 输出回地与输入回地。
- 给判据而不是感觉：**2oz 外层、ΔT≈20K 时 21A 约需 6.6mm 单层**（多层铜皮/多过孔并联可分摊）；其它电流档按 IPC-2221 折算。
- 用**过孔分布**佐证大电流网：0.3mm 孔每颗大约 1~2A 量级，大电流母线上只挂个位数过孔就要提醒补孔。

## 5. 隔离带口径（别拿早期过严口径否掉够用的板）

开槽 + 两侧间距按**工作电压**算：48V 级用 0.6mm 规则 + 2mm 槽就够（这是除隔离器内部屏障之外、PCB 侧要保证的部分）；只有要对外**宣称「整机 5kV 隔离」**时才需要 8mm 级爬电。按 5kV 写的早期文档口径不能直接当硬要求去否掉一块按 48V 设计、够用的板。

## 6. 报告格式（用户口径）

🔴必改 / 🟡建议 / 🟢小项 分级 + 逐条编号，每条写「位置 + 判据/依据」；先列已核过的干净项，再列要改的；「工具误报，不用管」单独一节并说明原因（单位/口径），别让计数把人吓住。
